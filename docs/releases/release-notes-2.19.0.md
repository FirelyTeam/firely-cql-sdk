## Firely CQL SDK 2.19.0

### tl;dr

> **Upgrading?** Here is the short version:
>
> - **Breaking changes:**
>   - **Build tooling** — `net8.0` is no longer a target framework. The SDK targets `net10.0` only, so an application still on .NET 8 must move to .NET 10 to take this release.
>   - **Runtime** — `ICqlOperators` gains `Avg` and `Median` over Quantities and four `Size` overloads for intervals, which a custom implementation must add.
>   - **Runtime (`Hl7.Cql.Elm`)** — messages for malformed ELM JSON are System.Text.Json's, and writing a type outside the ELM model throws `NotSupportedException`.
> - **Required migrations:**
>   1. Move applications on .NET 8 to .NET 10.
>   2. Re-verify measure output: list `except` with a null argument, `&` with a null operand, `Count` of a null list, quantity arithmetic across dimensions and the Firely .NET SDK `6.9.0` value set expansion change move CQL evaluation results.
>   3. Upgrade runtime and generated content together: libraries generated by 2.18.0 load on 2.19.0, but what 2.19.0 packages needs a 2.19.0 runtime (`GeneratorToolVersion` `6.2.2.0` → `6.4.0.0`).
> - **Highlights:**
>   - Reading and writing ELM JSON is two orders of magnitude faster: parsing CMS133 drops from 786 ms to 7.9 ms, and parsing FHIRHelpers-4.0.1 allocates about 2.5 MB instead of about 417 MB.
>   - `Size` of an interval, `Avg` and `Median` over Quantities, `GeometricMean`, `ToDate` and the `ToLong` overloads translate and evaluate, and include cycles are reported instead of overflowing the stack.

---

### Generated Code Compatibility

- `LibrarySetCSharpCodeGenerator.GeneratorToolVersion`: **`6.2.2.0` → `6.4.0.0`** (minor).
- Accepted by `LibraryInstanceInvoker_6_0`, whose supported range is `[6.0.0.0, 7.0.0.0)`.

Every step stays inside the invoker's range, so libraries generated by 2.18.0 load and run unchanged. Each step makes the generator handle CQL it failed on before:

- `6.2.3.0`: `Coalesce` past a value-type literal, and a null check of an expression that reduces to a literal, generate C# that compiles. (#1953)
- `6.3.0.0`: `Avg` and `Median` over a list of Quantities call the new `ICqlOperators` overloads. (#1961)
- `6.4.0.0`: `Size` of an interval calls the new `ICqlOperators.Size` overloads. (#1964)

For a library that compiled with 2.18.0, the generated C# is unchanged apart from the version in its `GeneratedCode` attribute, so regenerating is needed only for libraries that failed before. Do not ship what 2.19.0 generates to a host on an earlier SDK: a library compiled by 2.19.0 references the 2.19.0 SDK assemblies, and C# that calls `Avg`, `Median` or `Size` of these types needs `ICqlOperators` members that earlier runtimes lack.

### CQL SDK

#### New Public API

- **Runtime** — `ICqlOperators.Avg(IEnumerable<CqlQuantity?>?)` and `ICqlOperators.Median(IEnumerable<CqlQuantity?>?)`. (#1961)
- **Runtime** — `ICqlOperators.Size(CqlInterval<int?>?)`, `Size(CqlInterval<long?>?)`, `Size(CqlInterval<decimal?>?)` and `Size(CqlInterval<CqlQuantity?>?)`. (#1964)

#### Improvements

- **Runtime (`Hl7.Cql.Elm`)** — Parsing and writing ELM JSON (`Library.ParseFromJson`, `Library.LoadFromJson`, `Library.SerializeToJson`, `Library.WriteJson`) uses System.Text.Json's native polymorphism instead of a converter that built serializer options for every node. Parsing CMS133 drops from 786 ms to 7.9 ms and FHIRHelpers-4.0.1 from 480 ms to 2.9 ms; serializing CMS133 drops from 480 ms to 0.55 ms and FHIRHelpers-4.0.1 from 206 ms to 0.29 ms. Parsing FHIRHelpers-4.0.1 allocates about 2.5 MB instead of about 417 MB. (#1903, #1906)
- **Runtime (`Hl7.Cql.Elm`)** — Further savings around the serializer (#1907, #1909):
  - A process that writes ELM JSON both compact and indented, as the Packager CLI does when it saves compact ELM files and packages indented attachments, builds the serializer's metadata once instead of twice. Its first indented write allocates 0.8 to 2.7 MB instead of 84 to 87 MB, and a one-library process of that shape finishes about 90 ms (20%) sooner.
  - The ELM attachment of a packaged FHIR `Library` is written straight into UTF-8, and a library's kept source is re-formatted by copying tokens instead of building a `JsonDocument`. Indented, the attachment takes 0.41 to 0.50 of the time with 11 to 12% of the allocation when the source is re-formatted, and 0.28 to 0.56 of the time with 20 to 26% of the allocation when the library is serialized. Compact, it takes 0.67 to 0.86 of the time.
  - Saving translated ELM files serializes each library into a pooled buffer and writes the file once: one save allocates 54 to 135 KB instead of 0.5 to 4 MB, and takes 0.50 to 0.81 of the time.
  - Loading an ELM file with CR LF line endings normalizes them in one vectorized pass: CMS133 loads in 0.78 of the time and allocates 16% less.
  - Release builds no longer run the serializer's debug check, which boxed a default value for every property not marked as specified: 12.7 KB less per write of FHIRHelpers.
- **CQL-to-ELM translator** — `CqlToolkit.TranslateToElm()` translates the libraries in the order of their identifiers, so the same libraries record the same errors on every run, and a library that is translated keeps its builder, so a library translated later that includes it resolves it without parsing its CQL again. (#1874, #1892)

#### Dependency Updates

- **Runtime (`Hl7.Cql.Fhir`)** — `FirelyNetVersion`: `6.8.0` → `6.9.0`, bumping `Hl7.Fhir.Base` and `Hl7.Fhir.R4` for `Hl7.Cql.Fhir`, `Hl7.Cql.Packaging`, `Hl7.Cql.Packager` and the demo projects. A consumer with its own direct reference to the Firely .NET SDK should move it to `6.9.0` as well. No public API or generated C# output changes with it, but two behavior changes in `6.9.0` can change CQL evaluation results (#1934, #1935):
  - A value set without an expansion, which `ValueSetSource` expands itself, now counts nested codes towards its cap of 5,000 codes, so a nested expansion over the cap fails with `ValueSetExpansionTooBigException` instead of being accepted. An include that intersects value sets, or a code system with value sets, now keeps the nested codes it used to drop, so such a value set can have more members. A value set that arrives with its expansion is unchanged.
  - A FHIR `date`, `dateTime` or `time` value followed by a line break no longer converts to a CQL value; it becomes `null`. An `instant` followed by a line break makes the conversion throw the Firely .NET SDK's `CodedValidationException`, since reading `Instant.Value` throws for an invalid literal. A time without seconds still converts as before.
- **Runtime** — `FhirMetricsVersion`: `1.4.0` → `1.4.1`. The decimal overloads of `MetricServiceExtensions`, which the runtime uses for UCUM arithmetic and conversion, now parse a value an `IMetricService` returns in exponential notation, and refuse a value with a non-zero digit beyond the 28th decimal place instead of rounding it. Results with the default `FhirMetricService` are unchanged; a service injected through `FhirCqlContextOptions.MetricService` that writes exponential notation now works with them. `Hl7.Fhir.Base` `6.9.0` depends on this version. (#1897)

#### Potentially Breaking

- **Runtime** — `ICqlOperators` gains `Avg(IEnumerable<CqlQuantity?>?)` and `Median(IEnumerable<CqlQuantity?>?)`. They have no default interface implementations, so a custom `ICqlOperators` implementation fails to compile until both are implemented. A direct call with an untyped `null`, such as `operators.Avg(null)`, is now ambiguous between the Decimal and Quantity overloads; cast the argument, as in `operators.Avg((IEnumerable<decimal?>?)null)`. Generated C# always passes a typed argument. (#1961)
- **Runtime** — `ICqlOperators` gains `Size` for intervals of Integer, Long, Decimal and Quantity. It has no default interface implementation, so a custom `ICqlOperators` implementation fails to compile until the four overloads are implemented. (#1964)
- **Runtime (`Hl7.Cql.Elm`)** — Writing a subclass that is not part of the ELM model throws `NotSupportedException` instead of writing a `"type"` that nothing can read. (#1906)
- **Runtime (`Hl7.Cql.Elm`)** — The messages for malformed ELM JSON are System.Text.Json's and include the JSON path, for example `Read unrecognized type discriminator id 'Bogus'. Path: $.expression` instead of `Unknown type discriminator 'Bogus' for base type Expression`, and the same wording replaces `type property should be 'Library' but was 'Wrong'` for a library, a `VersionedIdentifier` and a tuple element. The exception type stays `JsonException`. Code that matches on the old message text needs to change. (#1906)
- **Runtime (`Hl7.Cql.Elm`)** — The `"type"` of an element of a `TupleTypeSpecifier` is validated: an unrecognized name, which was accepted before, throws a `JsonException`. (#1906)
- **CQL-to-ELM translator** — `ToLong(null)` is an ambiguous call, because an untyped null matches the new `Boolean` and `String` overloads as well as the `Integer` one. It used to translate, binding to the `Integer` overload. The Java reference translator reports the same error, as the Developer's Guide, *Function Resolution*, requires. Write `ToLong(null as Integer)` instead. (#1931)

#### Fixes

Several of the entries below **change CQL evaluation results**. See the Upgrade Checklist. Unless an entry says otherwise, the generated C# and `GeneratorToolVersion` are unchanged.

**Evaluation results**

- **Runtime** — List `except` follows CQL §9.B *Except* when either argument is null. A null first argument gives null; it used to give the second argument, so `null except { 1, 3, 5 }` was `{ 1, 3, 5 }`. A null second argument is treated as an empty list, so duplicates are removed from the result: `{ 1, 1, 2 } except null` is now `{ 1, 2 }`, where it used to be `{ 1, 1, 2 }`. (#1925)
- **CQL-to-ELM translator** — The `&` operator treats a null operand as the empty string, as CQL §9.B *Concatenate* requires: each operand of the translated `Concatenate` is wrapped in `Coalesce(X, '')`, as §6 *Translation Semantics* specifies. `'a' & null` used to be null and is now `'a'`. `+` is unchanged and still gives null when either operand is null. Regenerate ELM from CQL to pick it up. (#1933)
- **Runtime** — Adding or subtracting quantities whose units have different dimensions gives null, as CQL §9.B *Add* and *Subtract* require. `5.5 'cm' + 2 'cm2'` used to give `0.0552 'm'`, because the UCUM service combined the values without checking that the units measure the same dimension. Units of the same dimension, such as `'cm'` and `'m'`, are unaffected. (#1941)
- **Runtime** — `Count` of a null list gives `0`, as CQL §9.B *Count* requires. It used to give null, so `Count(X) = 0` over a null list was null and is now true. (#1947)

**Operators that now translate and evaluate**

- **Runtime and code generator** — `Avg` and `Median` over a list of Quantities, which translated but failed while the C# was built, evaluate per CQL §9.B: the result has the unit the quantities share, null elements are ignored, and a list with no non-null elements or a null list gives null. Quantities in different units give null with a warning, as `Sum`, `StdDev` and `Variance` do. `GeneratorToolVersion` moved to `6.3.0.0`. (#1961)
- **CQL-to-ELM translator, code generator and runtime** — `Size(Interval<T>)`, which reported "could not resolve function", translates and evaluates per CQL §9.B: `(end of argument - start of argument) + point-size`, so `Size(Interval[3, 7])` and `Size(Interval[3, 8))` are both 5. The point-size is 1 for Integer and Long and the Decimal minimum precision for Decimal and Quantity. A closed null boundary is the type's minimum or maximum, as in `Start` and `End`, so `Size(Interval[3, null])` runs to the maximum Integer. A null interval, an open null boundary, an interval over `Any` and a size outside the type's range give null. `GeneratorToolVersion` moved to `6.4.0.0`. (#1964)
- **CQL-to-ELM translator** — `GeometricMean(List<Decimal>)` translates, also for a list of Integer or Long values. It used to fail with "Could not resolve call to operator GeometricMean"; the runtime already implemented it. (#1947)
- **CQL-to-ELM translator** — `ToDate(DateTime)`, `ToDate(String)`, `ToLong(Boolean)` and `ToLong(String)`, which CQL §9.B *Type Operators* defines, translate. They used to fail with "Could not resolve call to operator". (#1931)
- **Runtime (`Hl7.Cql.Fhir`)** — A `FHIR.canonical` argument binds to a function parameter of type `FHIR.uri`, such as `FHIRHelpers.ToString(value uri)`. The FHIR model info declares `canonical` as a subtype of `uri`, but the .NET model holds `Canonical` and `FhirUri` as sibling types; the FHIR type converter now bridges that gap, as it already does for `id` and `code` to `string`. Libraries that failed to compile on such a call, including FHIRCommon 2.0.0's `url()` and `version()` fluent functions, compile and evaluate. (#1899)

**Translation and code generation**

- **CQL-to-ELM translator** — Libraries whose includes form a cycle, directly, through other libraries or by a library including itself, no longer make `CqlToolkit.TranslateToElm()` recurse until the stack overflows and the process ends. The include that closes the cycle is recorded in the ELM as an error naming the libraries along it, from the library that sorts first, so the error reads the same whatever order the libraries are added in; the other libraries translate. (#1874, #1892)
- **CQL-to-ELM translator** — A library's own function takes precedence over a System function it ties with during overload resolution. A library that defines, for example, `Width(I Interval<Integer>)` or `Size(I Interval<Date>)` and calls it unqualified reported "Call to operator Width(...) is ambiguous"; it now calls the library's function. (#1964)
- **CQL-to-ELM translator** — A model or an included library used as a value, including as an operand such as `FH + 1`, `FH[0]`, `-FH` or `start of FH`, is reported with an error reference instead of an internal `IncludeRef` or `UsingRef` node, so the ELM of that library can be serialized. `Floor(FH)` reports one error instead of two. (#1906)
- **Code generator** — Two expressions over a literal value generate C# that compiles. `GeneratorToolVersion` moved to `6.2.3.0`. (#1953)
  - `Coalesce(null, 15, null)` generated `(null as int?) ?? 15 ?? null as int?`, which C# rejects (CS0019) because `… ?? 15` is a plain `int`. A coalesce now stops at the first value-type literal, since no later operand can be reached.
  - A null check of an expression that reduces to a literal, such as `Message(5, false, …)`, generated `5 is null`, which C# rejects (CS0037). It now generates `false`.

**ELM JSON**

- **Runtime (`Hl7.Cql.Elm`)** — Reading ELM JSON whose `"type"` names an abstract class gives a `JsonException` instead of a `NotSupportedException`, and `"type": null` gives a `JsonException` naming the path instead of a `NullReferenceException`. (#1906)
- **Runtime (`Hl7.Cql.Elm`)** — Reading or writing ELM nested deeper than the thread's stack allows gives a `JsonException` instead of ending the process with a stack overflow. How deep that is depends on the stack: about 800 levels of nested expressions on a 1 MB stack, where previously about 450 were read before the process crashed, and about 4,000 on an 8 MB stack. `MaxDepth` stays 4,096. (#1906)
- **Runtime (`Hl7.Cql.Elm`)** — Packaging a library loaded from ELM nested more than 1,000 levels deep with `ElmAttachmentFormatting.Indented` or `ElmAttachmentFormatting.Compact` no longer fails while writing its ELM attachment. The attachment writer now takes the serializer's maximum depth of 4,096. (#1909)
- **Runtime (`Hl7.Cql.Elm`)** — `Library.LoadFromJson(FileInfo)` reads an ELM file that starts with a UTF-8 byte order mark instead of throwing `JsonException`, as `Library.LoadFromJson(Stream)` already did. (#1909)
- **Packaging** — An ELM attachment no longer starts with a byte order mark when the ELM file had one. JSON must not begin with one, and a consumer that parses the attachment as UTF-8 bytes rejected it. (#1909)

### CQL Packager

#### Breaking

- None.

#### Improvements

- `replace-library-attachments` reads ELM bytes through a stream instead of a decoded string, which allocates 21 to 38% less once warm. (#1909)
- `replace-library-attachments` updates the CQL options parameter and extension from an ELM file that starts with a UTF-8 byte order mark, where it used to log a warning and leave them unchanged. Packaging ELM bytes on their own, without a parsed library, accepts such a file instead of throwing `JsonException`. (#1909)
- Packaging picks up the translator, code generator and runtime changes above.

### Demo Projects and Build Tooling

#### Breaking

- **`net8.0` is no longer a supported target framework.** The SDK targets `net10.0` only. .NET 8 reached [End of Support on 10 November 2026](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/), and CQL SDK 2.x support for it ended on the same date — see [discussion #1426](https://github.com/FirelyTeam/firely-cql-sdk/discussions/1426). Applications still running on .NET 8 must move to .NET 10 to take this release. (#1427, #1810)
- The legacy `Cql-Sdk-All.sln` is removed in favour of `Cql-Sdk-All.slnx`. The `Cql-Sdk.slnf` and `Cql-Sdk-Demos-Examples.slnf` solution filters point at `Cql-Sdk-All.slnx`; nothing else in them changed. Anything referencing the solution by filename — scripts, pipelines, IDE configuration — needs to use the new name. (#1810)
- A `global.json` pins the .NET SDK to 10.0 (`10.0.100`, rolling forward to the latest installed 10.0 feature band and patch). A machine that also has a newer SDK, such as .NET 11's, builds this repository with the .NET 10 SDK, as CI does. Building it needs a .NET 10 SDK installed. (#1810)
- The `test-multiframework.ps1` and `test-multiframework.sh` scripts are removed. Run `dotnet test` on the test projects directly. `build.ps1` and `build.sh` no longer accept `--framework net8.0`, and their interactive prompt asks only for the build configuration. (#1810, #1902)

#### Improvements

- `LangVersion` is pinned to a specific C# version instead of `latest`, which resolved to whatever the installed SDK supports rather than to the target framework's default. (#1810)
- The CQL conformance suite is synced with upstream [cqframework/cql-tests](https://github.com/cqframework/cql-tests), and each XML case shows separately in Test Explorer. Cases that do not hold for this SDK are listed with their reason in `SkippedTests.cs`. (#1901, #1911, #1913, #1915, #1917, #1919, #1921, #1923, #1941, #1947, #1950, #1953, #1964)
- The translator census loads the QICore and USCore model infos bundled in `Hl7.Cql.Model` instead of XML copies in the test inputs, which are deleted; its results are unchanged. (#1965)
- Leftovers of the first cleanup sweep are removed, and the internal `ReflectionUtility` moves to the `Hl7.Cql.Abstractions.Infrastructure` namespace. Neither changes public API or behavior. (#1894, #1895)

### Upgrade Checklist

1. **Move applications on .NET 8 to .NET 10.** The packages no longer contain `net8.0` assemblies.
2. **Re-verify measure output.** List `except` with a null argument, `&` with a null operand, `Count` of a null list, `+` and `-` of quantities of different dimensions, and value sets that `ValueSetSource` expands itself move CQL evaluation results. Treat moved scores for affected measures as expected rather than as new defects. Regenerate ELM from CQL to pick up the `&` change.
3. **Upgrade runtime and generated content together.** Libraries generated by 2.18.0 still load, since the invoker accepts `[6.0.0.0, 7.0.0.0)`, and regenerating them changes only the version marker. Do not ship what 2.19.0 packages to a host still on an earlier SDK.
4. **If you implement `ICqlOperators` yourself**, add `Avg` and `Median` over `IEnumerable<CqlQuantity?>?` and the four `Size` overloads, and cast an untyped `null` passed to `Avg` or `Median`.
5. **If you reference the Firely .NET SDK directly**, move it to `6.9.0`.
6. **If you match on the message of a `JsonException` from reading ELM**, match on System.Text.Json's wording, which includes the JSON path.
7. **If your CQL calls `ToLong(null)`**, write `ToLong(null as Integer)`.
8. **If you build this repository**, use `Cql-Sdk-All.slnx` and a .NET 10 SDK.

### Common Items To Check

- PublicAPI shipped/unshipped promotions: 6 entries, all in `Cql.Runtime`: the `ICqlOperators` `Avg` and `Median` overloads over Quantities and the four `Size` overloads. No `*REMOVED*` entries.
- New or changed exception types: reading malformed ELM JSON throws `JsonException` with System.Text.Json's messages in more cases, where it threw `NotSupportedException`, `NullReferenceException` or overflowed the stack; writing a type outside the ELM model throws `NotSupportedException`. No new `ICqlError` types.
- Public runtime/operator API changes: `ICqlOperators` gains `Avg`, `Median` and `Size` overloads, without default implementations.
- Generator version and invoker range: stated above under `### Generated Code Compatibility`; the generator moved to `6.4.0.0`, and the range did not move.
- `FirelyNetVersion`: `6.8.0` → `6.9.0`, the latest Firely .NET SDK release. Vonk's `FhirNetApiVersion` on `develop` is also `6.9.0` at cut time, so the two are equal.
- Packager CLI argument changes: none.
- MSBuild property, target or script-flag changes: `net8.0` dropped from `TargetFrameworks`, `Cql-Sdk-All.sln` replaced by `Cql-Sdk-All.slnx`, `--framework net8.0` removed from the build scripts, and the multi-framework test scripts removed (see Demo Projects and Build Tooling).
- Content previously drafted in `docs/releases/vnext-release-notes.md`: none (static pointer doc).
