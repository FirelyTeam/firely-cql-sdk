## New Public API

- **Invocation toolkit** — `InvocationToolkit.ReadCqlAssemblyInfo(AssemblyBinary)` reads the CQL libraries in an
  assembly from its metadata, without loading it. It returns a `CqlAssemblyInfo` holding the assembly's name, the
  `AssemblyBinary` it was read from, and `Libraries`: one `CqlLibraryInfo` per library, keyed by the library's
  identifier, each with the version of the code generator that wrote it and whether the toolkit runs that version.
  `CqlAssemblyInfo.IsSupported` is true when the assembly holds at least one CQL library and the toolkit runs them all.
  Bytes that cannot be read, such as an assembly a host received from elsewhere in the `+dll` attachment of a FHIR
  Library, do not throw: the result's `CqlAssemblyInfo.Error` says why, and it lists no libraries. A library the
  assembly declares in a way the toolkit does not accept, such as a type that carries two `CqlLibraryAttribute`s or a
  library two types declare, is listed with a `CqlLibraryInfo.Error` while the rest of the assembly is still read.
  `CqlAssemblyInfo.HasErrors` says whether the assembly or any of its libraries has an error.
  `InvocationToolkit.IsGeneratorToolVersionSupported(Version)` answers whether the toolkit runs code from a
  given generator version, and `CreateLibrarySetInvoker` applies the same rules. A host can therefore check a library
  before loading it, reject it or compile it from its ELM instead, and pass `CqlAssemblyInfo.AssemblyBinary` to
  `AddAssemblyBinaries` when it is supported. (#1824)

## Potentially Breaking

- **Code generator** — generated library types now carry `[GeneratedCode("Hl7.Cql.CodeGeneration.NET", "6.1.0.0")]`
  instead of `[GeneratedCode(".NET Code Generation", …)]`, and `GeneratorToolVersion` moves from 6.0.3.0 to 6.1.0.0.
  The invocation toolkit recognizes both names, so libraries generated before this release keep loading. Earlier
  releases of the toolkit recognize only `.NET Code Generation`, so they skip libraries generated by this release. A
  host that compares the tool name itself must accept the new name, or call `InvocationToolkit.ReadCqlAssemblyInfo`
  instead. The generated C# otherwise does not change. (#1824)
- **Invocation toolkit** — `CreateLibrarySetInvoker` now skips, with an error in the log, a library type that carries
  more than one `CqlLibraryAttribute` or `GeneratedCodeAttribute`, and every type of a library that more than one type
  declares, and loads the other libraries. That includes one library in two assemblies added to the same toolkit,
  such as `FHIRHelpers` compiled into the `+dll` of two FHIR Libraries: both copies are skipped.
  `ReadCqlAssemblyInfo` reads one assembly at a time, so it reports each copy as supported, and a host that adds
  several assemblies has to look for an identifier they share itself. Before, any of these made
  `CreateLibrarySetInvoker` throw (`AmbiguousMatchException` or `ArgumentException`) and no library loaded. (#1824)
