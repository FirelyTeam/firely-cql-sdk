## New Public API

- `IEnumerable<object?>? PromoteLateBoundToList(object? argument)` on `Hl7.Cql.Operators.ICqlOperators`,
  emitted by the compiler for a query source whose static type is `object` (#1600). It has no default
  interface implementation, so a custom `ICqlOperators` implementation must add it.

## Fixes

- **Code generator:** a query whose source is a *late-bound* list-valued property — one reached
  through a choice or union type, which the ELM leaves untyped and the code generator surfaces as
  `object` — now iterates that list's elements instead of treating the list itself as the query's
  single element. The generator decided list-vs-singleton from the source expression's static type;
  for a late-bound source that type is `object`, so the value was wrapped in a one-element array and
  every element access inside the query body saw a `List<T>` where a `T` was expected, yielding
  `null` with no error. The promotion is now made on the runtime value
  (`ICqlOperators.PromoteLateBoundToList`), and the paired `singleton from` demotion is skipped when
  the ELM declares the query result to be a list, so a property holding more than one element is no
  longer truncated. CMS69 `reasonCode in "Overweight or Obese"` over
  `[ServiceRequest] union [MedicationRequest]` is the pattern this affects. **CQL evaluation results
  change:** a define containing this pattern previously scored as if the property were empty and now
  returns its values, so measure output can move. `GeneratorToolVersion` is bumped to `5.3.0.0`; see
  "Potentially Breaking" below. (#1600)

## Potentially Breaking

- The C# generated for a query over a late-bound list-valued source now calls the new
  `ICqlOperators.PromoteLateBoundToList`, so the generator tool version moves 5.2.1.0 → **5.3.0.0** — a
  minor bump, because generated code from this version has a hard dependency on a runtime that provides
  the member. Pairing 5.3.0.0 generated libraries with an older `Hl7.Cql.Runtime` is not supported: such
  libraries fall outside the older invocation toolkit's supported generator range and are skipped at load
  with a warning rather than loading and failing with `MissingMethodException` inside a definition body.
  Consumers who check in generated C#, or who ship packaged FHIR `Library` resources with embedded
  C#/assemblies, should regenerate when upgrading, and upgrade runtime and generated content together.
  Custom `ICqlOperators` implementations fail to compile until `PromoteLateBoundToList` is implemented.
  (#1600)

  `LibraryInstanceInvoker_5_0`'s supported range widens to `[5.1.0.0, 5.4.0.0)` to accept the new
  version. No method signature, library shape or generated-code attribute shape changed, so no new
  invoker is needed and existing invokers keep working for content generated by either version.
