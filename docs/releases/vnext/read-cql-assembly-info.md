## New Public API

- **Invocation toolkit** — `InvocationToolkit.ReadCqlAssemblyInfo(AssemblyBinary)` reads the CQL libraries in an
  assembly from its metadata, without loading it. It returns a `CqlAssemblyInfo` holding the assembly's name, the
  `AssemblyBinary` it was read from, and `Libraries`: one `CqlLibraryInfo` per library, keyed by the library's
  identifier, each with the version of the code generator that wrote it and whether the toolkit runs that version.
  `TryReadCqlAssemblyInfo` does the same without throwing, for an assembly a host received from elsewhere, such as the
  `+dll` attachment of a FHIR Library. `InvocationToolkit.IsGeneratorToolVersionSupported(Version)` answers whether
  the toolkit runs code from a given generator version, and `CreateLibrarySetInvoker` applies the same rule. A host can
  therefore check a library before loading it, reject it or compile it from its ELM instead, and pass
  `CqlAssemblyInfo.AssemblyBinary` to `AddAssemblyBinaries` when it is supported. (#1822)

## Potentially Breaking

- **Code generator** — generated library types now carry `[GeneratedCode("Hl7.Cql.CodeGeneration.NET", "6.1.0.0")]`
  instead of `[GeneratedCode(".NET Code Generation", …)]`, and `GeneratorToolVersion` moves from 6.0.3.0 to 6.1.0.0.
  The invocation toolkit recognizes both names, so libraries generated before this release keep loading. Earlier
  releases of the toolkit recognize only `.NET Code Generation`, so they skip libraries generated by this release. A
  host that compares the tool name itself must accept the new name, or call `InvocationToolkit.ReadCqlAssemblyInfo`
  instead. The generated C# otherwise does not change. (#1822)
