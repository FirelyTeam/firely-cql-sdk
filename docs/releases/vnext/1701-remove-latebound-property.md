## Breaking

- **`ICqlOperators.LateBoundProperty` is removed, and a property the compiler cannot bind is a build
  error.** Property access on a choice-typed value dispatches over the choice's alternatives at
  compile time, so generated code no longer needs to resolve a property by reflection at run time.
  Where the compiler still cannot bind a property, it now fails the build at that ELM node instead
  of emitting a late-bound read. The error names the library, the CQL line and the property, and
  asks for an explicit `as` of the source to the type that has the element. That covers:
  - a path segment that neither the source's type nor any known alternative of its choice type has,
    including a sort by such a column;
  - a choice with an alternative whose type does not resolve, or that erases a choice without
    declaring its alternatives. Such a library used to build with a late-bound branch for that
    alternative (#1645);
  - an element whose type on an alternative does not convert to the type the ELM expects.

  An alternative that is itself a choice is no longer treated as uninspectable: its alternatives are
  dispatched over like the others.

  `ICqlOperators.LateBoundProperty<T>(object?, string)` and its implementation in `CqlOperators`
  are removed from the public API. `FlattenLateBoundList` stays.

  **This changes generated C#**: `GeneratorToolVersion` moves to `6.0.0.0` (major: code generated by
  5.x may call `LateBoundProperty`), and the invoker toolkit now accepts generator versions
  `[6.0, 7.0)`. Libraries generated by a 5.x generator are skipped with a warning and must be
  regenerated. Every checked-in generated library is regenerated. CQL evaluation results do not change for
  any library that builds; a library that relied on a late-bound read no longer builds. (#1691, #1701)
