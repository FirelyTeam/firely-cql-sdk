## Firely CQL SDK 2.16.0

> [!WARNING]
> **.NET 8 support ends on 10 November 2026.** Microsoft's .NET 8 reaches
> [End of Support](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/) on that date, and
> CQL SDK 2.x support for .NET 8 ends with it — see
> [discussion #1426](https://github.com/FirelyTeam/firely-cql-sdk/discussions/1426) for the full
> announcement. This release still ships `net8.0` alongside `net10.0`; plan your move to .NET 10
> (Microsoft's current LTS) before that date. Progress on removing the target is tracked in
> [#1427](https://github.com/FirelyTeam/firely-cql-sdk/issues/1427).

### tl;dr

> **Upgrading?** Here is the short version:
>
> - **Breaking changes:** `ICqlOperators.LateBoundProperty` is removed and a property the compiler cannot bind is now a build error; `ICqlOperators` gains an abstract `AnyRelated<T>`; `CqlTime.Successor()`/`Predecessor()` return `CqlTime?`; the `AllowNullIntervals` translator option defaults to `true`; eight internal operators (`Between`, `NotEqual`, `Case`, `ToList`, `MinValue`, `MaxValue`, `Interval`, `ProperBetween`) are no longer callable with function syntax.
> - **Required migrations:** **Regenerate every packaged artifact and checked-in `*.g.cs`** — `GeneratorToolVersion` moves `5.2.1.0` → `6.0.0.0` and the invoker now accepts only `[6.0.0.0, 7.0.0.0)`, so libraries generated by a 5.x generator are skipped with a warning at load. Re-verify measure output: a large number of fixes in this release move CQL evaluation results. Custom `ICqlOperators` implementers must implement `AnyRelated<T>`.
> - **Highlights:** Property access on choice-typed values is now dispatched at compile time instead of resolved by reflection, which makes reference-based medication retrieves and list-valued choice elements evaluate correctly for the first time.

### Generated Code Compatibility

- `LibrarySetCSharpCodeGenerator.GeneratorToolVersion`: **`5.2.1.0` → `6.0.0.0`** (major).
- Accepted by `LibraryInstanceInvoker_6_0`, whose supported range is `[6.0.0.0, 7.0.0.0)`.

**This is a major generator bump and it is not optional to act on.** Code generated by a 5.x generator may call `ICqlOperators.LateBoundProperty`, which no longer exists, so the invoker toolkit skips such libraries with a warning instead of running them. Regenerate every checked-in `*.g.cs` and every packaged FHIR `Library` resource with embedded C# or assemblies, and upgrade runtime and generated content together.

The version passed through `5.2.2.0` (#1639), `5.2.3.0` (#1629), `5.3.0.0` (#1670), `5.3.1.0` (#1646), `5.3.2.0` (#1667) and `5.3.3.0` (#1677) on the way; only the final value matters to a consumer.

### CQL SDK

#### New Public API

- `ICqlOperators.AnyRelated<T>(IEnumerable<T>? related, Func<T, bool?> suchThat)` — see **Potentially Breaking**, since it is abstract.
- `Hl7.Cql.Primitives.CqlPointFromNonUnitIntervalError`, thrown as `CqlException<CqlPointFromNonUnitIntervalError>` by `point from` over a non-unit interval, where an `InvalidOperationException` was thrown before. (#1625)

#### Improvements

- **A reference tested with `is` has the tested type within the branch it guards.** A `case` whose leading conditions are `is` tests of one function operand, query alias or `let`, and an `if` whose condition is such a test, compile to a type switch whose arms bind the reference as the tested type. Within a branch, `x as T` is the value itself rather than a cast, and a property of `x` binds against `T` rather than dispatching over the choice's alternatives. A branch an earlier test already covers is dropped. (#1661, #1677)
- **An `as` to a type its operand already has emits no cast**, removing casts throughout generated code. (#1683)
- **Translating CQL to ELM and compiling ELM to assemblies are safe to run on several threads in one process**, each with its own `CqlToolkit` and `ElmToolkit`. The process-wide ELM `localId` generator was not thread-safe — concurrent work could fail with `IndexOutOfRangeException` or hang — and it retained every element it had numbered for the life of the process. Ids are now assigned without keeping their elements alive. (#1671)

#### Dependency Updates

- **Build tooling:** external package versions are now managed centrally in a root `Directory.Packages.props` instead of per-project. Internal to how the SDK is built. (#1615)
- **Documentation:** the root `README.md`'s "External Dependencies" table has been removed because it restated pinned versions by hand and drifted. Read [`Directory.Packages.props`](https://github.com/FirelyTeam/firely-cql-sdk/blob/develop/Directory.Packages.props) instead — it is what the build uses, so it cannot be out of date. (#1615)
- `FirelyNetVersion`: `6.5.0` → `6.6.0`, bumping `Hl7.Fhir.Base` and `Hl7.Fhir.R4` for every package that consumes Firely .NET SDK types (`Hl7.Cql.Fhir`, `Hl7.Cql.Packaging`, `Hl7.Cql.Packager`) and for the demo projects. A consumer with its own direct reference to the Firely .NET SDK should move it to `6.6.0` as well. No public API, generated C# output, or CQL evaluation result changes with it. (#1710)
- `MicrosoftExtensionsVersion`: `10.0.3` → `10.0.9`, moving the whole `Microsoft.Extensions.*` family together. `Hl7.Fhir.Base` `6.6.0` depends on `Microsoft.Extensions.Caching.Memory` `10.0.9`, which requires `Microsoft.Extensions.Logging.Abstractions` at that version or newer, so the dependency floor the affected `Hl7.Cql.*` packages declare rises accordingly. An application already resolving `10.0.9` or newer is unaffected. (#1710)
- `Microsoft.Extensions.Logging.Abstractions` was separately pinned at `10.0.7` and is folded back into the family property, and with it `Microsoft.Extensions.DependencyInjection.Abstractions` and `System.Diagnostics.DiagnosticSource`. (#1615)

  **Net effect across this release**, since the two changes above touch the same packages: `Microsoft.Extensions.Logging.Abstractions` and the rest of the `Microsoft.Extensions.*` family end at `10.0.9`. The intermediate drop to `10.0.3` from unpinning is not a state any released version is in.

#### Potentially Breaking

- **`ICqlOperators.LateBoundProperty<T>(object?, string)` and its `CqlOperators` implementation are removed.** Property access on a choice-typed value now dispatches over the choice's alternatives at compile time, so generated code no longer resolves properties by reflection. Where the compiler still cannot bind a property it **fails the build** at that ELM node, naming the library, the CQL line and the property, and asking for an explicit `as` of the source to the type that has the element. That covers a path segment no alternative has (including a sort by such a column), a choice with an unresolvable or undeclared alternative, and an element whose type on an alternative does not convert to the type the ELM expects. `FlattenLateBoundList` stays. (#1691, #1701)
- **`ICqlOperators` gained the abstract member `bool? AnyRelated<T>(IEnumerable<T>? related, Func<T, bool?> suchThat)`**, called by generated code for a relationship clause over a list source in place of `WhereAny`. It has no default interface implementation, so **a custom `ICqlOperators` implementation does not compile until it implements it**: `true` when `suchThat` is `true` for at least one element of `related` (null elements included), otherwise `false`, and `false` for a null `related`. (#1669, #1670)
- **`CqlTime.Successor()` and `CqlTime.Predecessor()` return `CqlTime?` instead of `CqlTime`**, since the successor of the maximum time and the predecessor of the minimum time are `null`. Callers that dereferenced the result unconditionally get a nullable warning. (#1620)
- **The `AllowNullIntervals` translator option defaults to `true`** (`CqlToElmOptions.AllowNullIntervals` and the `CqlToolkitConfig` constructor parameter). Consumers relying on the translator rejecting `Interval[null, null]` and `Interval(null, null)` must pass `AllowNullIntervals: false` explicitly. The Packager CLI example configuration carries the same default. (#1631)
- **Eight internal operators are no longer callable with function syntax**: `Between`, `ProperBetween`, `Interval`, `NotEqual`, `Case`, `ToList`, `MinValue` and `MaxValue`. CQL defines no function of those names and the reference translator rejects the calls; they resolved here only because every `SystemLibrary` field was reflected into the function symbol table. Such a call now reports `Could not resolve call to operator <Name> with signature (...)`. The operator syntax (`between`, `!=`, `Interval[...]`, `case`, `minimum`, `maximum`, implicit list promotion) is unchanged. (#1634)

#### Fixes

Many of the entries below **change CQL evaluation results**. See the Upgrade Checklist.

**Property access and choice types**

- **Property access on a choice-typed value is dispatched at compile time.** The compiler enumerates the choice's alternatives and emits a dispatch with one arm per alternative that has the element, `null` for the others, evaluating the value once. Alternatives reading the element through a common base or interface share an arm. Where every alternative agrees on the element's type, the result has that plain type. At former late-bound sites an empty list-valued element now evaluates to the empty list rather than `null`, and a failing conversion surfaces instead of degrading to `null`. (#1647, #1667)
- **The value of a FHIR primitive has the type the model declares.** For every primitive whose .NET representation differs from the declared System type (`date`, `dateTime`, `instant`, `time`, `base64Binary`), the value converts to the declared System type wherever the ELM did not state it. `FHIR.positiveInt` and `FHIR.unsignedInt` resolve to `PositiveInt` and `UnsignedInt` rather than `Integer`, so a test for or cast to those types now matches real values. (#1647, #1667)
- **Qualified (dotted) property paths resolve in late-bound property access**, splitting the path and resolving each segment against the runtime type of the preceding segment's value. The affected paths are the translator's standard expansion of `[MedicationRequest: "<valueset>"]` into a medication-by-reference join, so **any medication retrieve resolved through `MedicationRequest.medicationReference` previously returned no rows and now matches**. (#1638)
- **Qualified property paths are bound at compile time** where the alias is strongly typed, one segment at a time, late-binding only from the first segment that is not statically known. The source-based form previously returned the partially walked value for a path it could not fully bind, so comparisons against such a path silently failed and now match. (#1646)
- **Late-bound property access keeps list cardinality.** A list-valued element of a choice source was emitted as a scalar, wrapped in a one-element array and cast, yielding `null`; filters over it evaluated against `null` and produced wrong results in both directions without signalling an error. (#1639)
- **CQL-to-ELM translator:** member access on a choice-typed value, such as `C.onset.value`, translates instead of reporting `Type Choice<…> has no members.` (#1648, #1700)

**Intervals and boundaries**

- **Exclusive interval boundaries stay exclusive.** The `Interval` selector no longer normalizes an exclusive date, dateTime or time boundary to a closed boundary one unit inward. That normalization was lossless only at the value's own precision, so a timing phrase comparing at a coarser precision — `6 months or less before day of start of X` — silently became inclusive. `in` now applies the exclusive comparison the specification requires, and `contains` shares that implementation. (#1602)
- **Interval operators defined "using the semantics described in the Start and End operators" compare effective boundaries** rather than raw endpoints: `starts`, `ends`, `includes`/`included in`, `properly includes`/`properly included in`, `intersect`, `point from`, and the ordering `collapse` merges in. (#1602)
- **FHIR `Period` conversion preserves exclusive interval semantics** by stepping an exclusive date/time boundary inward by one unit of its precision. An exclusive boundary at the point type's limit is emitted unstepped instead of throwing or emitting an invalid FHIR value. (#1602)
- **`Interval[null, null]` is the maximal interval**, not `null`: a closed null boundary means the minimum or maximum of the point type, while an open null boundary is unknown. `after`, `before`, `same or before`, `same or after`, `starts`, `ends`, `union`, `point from`, `start of`, `end of` and interval equality now follow these Start/End semantics. (#1625, #1629)
- **`properly included in`/`properly includes` apply Start/End boundary semantics**, and an indeterminate boundary comparison yields `null` rather than `true`. `Successor` of the maximum and `Predecessor` of the minimum of Integer, Long, Decimal, Quantity and Time return `null` instead of wrapping. Adding to or subtracting from a Time returns `null` when the result leaves the day. `Expand` no longer throws on unknown or closed-null boundaries and emits the final partition. (#1620)
- **`intersect` applies Start/End boundary semantics** instead of returning `null` whenever a boundary value is null. (#1693)
- **`in` and `includes` with a point return `null` when a boundary comparison is `null`** — for a Date, DateTime or Time point less precise than the matching boundary, or quantities with invalid or incommensurable units. They returned `true` at a closed boundary and `false` at an open one. (#1684)
- **`overlaps`, `overlaps before`/`after`, `meets`, `meets before`/`after` return `null` on an uncertain boundary comparison** rather than `false`. A comparison the other boundary settles is still decided. (#1689)
- **`after`/`before` with one point and one interval operand** use the point-interval and interval-point overloads instead of promoting the point to an interval. (#1626, #1632)
- **Scalar `after`/`before` return `null` when either operand is null**, as §9.B requires. Previously the point comparison fell through to the comparer's total ordering of null and returned a boolean — all six null combinations now yield `null`. (#1598)
- **An interval selector with two untyped `null` boundaries translates to `Interval<Any>`** instead of raising a translation error, matching the reference translator. (#1631)

**Operators and conversion**

- **`HighBoundary`/`LowBoundary` with a null precision use the greatest precision of the input's type** instead of returning `null`, keep every component the input has, and complete a Decimal's missing decimals on the digits of the magnitude. **For a Decimal**, whose greatest precision is 8, a precision beyond 8 is `null` rather than accepted or throwing. DateTime and Time carry higher precisions and are unaffected: `HighBoundary(@T10:30:15.250, 9)` is `@T10:30:15.250` and `HighBoundary(@2014-02, 17)` is `@2014-02-28T23:59:59.999`, where the latter previously threw `ArgumentException`. (#1694)
- **`years between` a 29 February start and 28 February of a non-leap year counts that day as the anniversary**, so `years between @2012-02-29 and @2014-02-28` is `2`. `AgeInYears()` and `AgeInYearsAt()` follow. (#1685)
- **`with`/`without` evaluate `such that` for null elements of the related list.** The clause compiled to `exists (R where c)`, and `exists` ignores null elements, so a null element could never satisfy the clause even when the author's `such that` accepted it. An author's own `exists (X where c)` is unchanged. (#1669, #1670)
- **A query's `return all` clause is honoured.** The front end never read the `all`/`distinct` modifier and `ReturnClause.distinct` defaults to `true`, so `return all` was translated as `return distinct` and silently dropped duplicates. Libraries packaged from Java-translated ELM are unaffected. (#1643)
- **Converting a FHIR `base64Binary` to a CQL `String` yields the base64 text**, as FHIR defines it, rather than a UTF-8 decoding of the bytes. (#1665)
- **`Combine` returns `null` for an empty source list** and ignores null elements, returning `null` when none remains, instead of an empty string and doubled separators. (#1619, #1622)
- **Decimal equivalence (`~`) determines precision ignoring trailing zeros** and rounds the more precise operand away from zero, so `1.001 ~ 1.000` is `true` and `1.5 ~ 1.55` is `false`. **String equivalence ignores case and treats all whitespace as equivalent.** Equality, ordering and hash-based operators stay ordinal. (#1619)
- **Equivalence (`~`) resolves its comparer the same way equality does**, including through a base type's registration, instead of throwing `ArgumentException`. (#1679)
- **`DateIso8601.TryParse`/`DateTimeIso8601.TryParse` return `false` for a date that does not exist** — `2026-13-45`, or 29 February in a common year — instead of throwing. The runtime uses these for FHIR date values, so a Patient with an impossible `birthDate` now yields `null` where evaluation threw. (#1660)

**Translator diagnostics**

- **A retrieve that filters by terminology carries the property it filters on and how**: `codeProperty` from the model's primary code path, `codeComparator` `in` for a list/value set/code system and `~` for a code or concept. A retrieve with an authored path and a single code filtered on `code` and now filters on the authored path. The data requirements analyzer now sees a path on every terminology retrieve. (#1651, #1652)
- **A translation error naming argument types is reported instead of being replaced by a `NullReferenceException`.** An unresolved type renders as `(missing)`. (#1654, #1655)
- **A query whose source cannot be resolved reports `Could not resolve identifier …`** instead of throwing `InvalidOperationException`. (#1657, #1659)
- `MinValue()`/`MaxValue()` report a resolution error instead of throwing `ArgumentException`; a user-defined function named `NotEqual` resolves; a system function called with function syntax runs the same validators as its operator form. (#1633, #1634)
- `@2026-13-45` reports `Unparseable date literal` instead of throwing out of translation. (#1660)

### Upgrade Checklist

1. **Regenerate everything.** `GeneratorToolVersion` is now `6.0.0.0` and the invoker accepts only `[6.0.0.0, 7.0.0.0)`. Libraries generated by a 5.x generator are skipped with a warning at load, not silently run. Regenerate checked-in `*.g.cs` and packaged FHIR `Library` resources with embedded C#/assemblies, and upgrade runtime and generated content together.
2. **Expect some libraries to stop building.** A property the compiler cannot bind is now a build error rather than a late-bound read. The error names the library, CQL line and property; add an explicit `as` of the source to the type that has the element.
3. **If you implement `ICqlOperators` yourself, implement `AnyRelated<T>`.** There is no default interface implementation, so your implementation will not compile until you do.
4. **Re-verify measure output.** A large number of fixes in this release move CQL evaluation results — interval boundary semantics, null propagation in comparisons, choice-typed property access, medication-by-reference retrieves, `return all`, leap-day age arithmetic and base64 conversion among them. Treat moved scores for affected measures as expected rather than as new defects.
5. **If you pass `AllowNullIntervals: false` implicitly by relying on the old default, pass it explicitly.**
6. **If you call `Between`, `NotEqual`, `Case`, `ToList`, `MinValue`, `MaxValue`, `Interval` or `ProperBetween` with function syntax, rewrite them as operators.**
7. **If you are on `net8.0`, plan the move to `net10.0`** — see the warning at the top of this document.
